Compressão de Textos

Como guardar um texto ocupando menos espaço, trocando cada palavra por um código de bits. Aqui o foco é entender o porquê de cada passo; o código aparece só para ajudar a enxergar a ideia.

Como estudar esta matériaNa prova, compressão não cobra exercício de código. Cobra os conceitos: o que é razão de compressão, como a árvore de Huffman é montada, o que é árvore canônica, para que servem as três fases de Moffat e Katajainen, como funcionam Base e Offset. Os pseudocódigos estão aqui só como apoio.

1Por que comprimir

Comprimir é representar o texto original em menos espaço, trocando os símbolos do texto por outros que ocupam menos bits ou bytes.

Ganho

O texto ocupa menos espaço, então leva menos tempo para ser lido do disco, transmitido pela rede e pesquisado.

Preço

Custo de processamento para codificar e decodificar o texto.

O que mais importa além do espaço

  • Velocidade de compressão e de descompressão. Muitas vezes descomprimir rápido importa mais que comprimir rápido. Num banco de dados textual, o texto é comprimido uma vez e lido muitas.
  • Casamento de cadeias direto no texto comprimido. Procurar a cadeia já comprimida pode ser bem mais eficiente do que descomprimir tudo para procurar.
  • Acesso direto a qualquer parte do texto comprimido, podendo descomprimir a partir dali. Um sistema de recuperação de informação com grandes coleções precisa disso.

2Razão de compressão

É a porcentagem que o arquivo comprimido representa em relação ao original. Mede o ganho de espaço de um método.

razão = tamanho comprimido / tamanho original × 100%

Exemplo: original com 100 bytes, comprimido com 30 bytes: razão de 30%.

Cuidado com a leituraRazão menor é melhor. 30% quer dizer que sobrou 30% do tamanho (economizou 70%).

3A ideia de Huffman

Proposto em 1952, é um dos métodos de codificação mais conhecidos.

  • Cada símbolo diferente do texto recebe um código único, de tamanho variável.
  • Símbolos frequentes ganham códigos curtos; símbolos raros ganham códigos longos.
  • As implementações tradicionais usam caracteres como símbolos.
IntuiçãoÉ como abreviar o que você mais escreve. Se "rosa" aparece toda hora, vale muito a pena que ela vire um único bit, mesmo que palavras raras fiquem com códigos maiores.

Para sistemas de recuperação de informação (RI), o melhor é usar palavras como símbolos:

Huffman por caracteres

Comprime o texto para cerca de 60%.

Huffman por palavras

Comprime o texto para cerca de 25%.

4Huffman usando palavras

É a técnica mais eficaz para textos em linguagem natural.

  1. Cada palavra diferente vira um símbolo. Conta-se a frequência de cada uma e gera-se o código de Huffman.
  2. Comprime substituindo cada palavra pelo seu código.

Por isso a compressão faz duas passadas no texto: uma para contar as frequências e outra para comprimir.

Bônus: integração com arquivo invertidoA tabela de símbolos do codificador é exatamente o vocabulário do texto. Isso casa naturalmente com o arquivo invertido usado em sistemas de RI.

E os espaços e a pontuação?

O texto tem palavras e separadores (espaço, vírgula, ponto...). Truque: o espaço simples fica implícito.

  • Palavra seguida de um espaço simples: codifica só a palavra.
  • Caso contrário: a palavra e o separador são codificados separadamente.
  • Na decodificação, supõe-se que depois de cada palavra vem um espaço, a não ser que o próximo símbolo seja um separador.

Texto: "para cada rosa rosa, uma rosa é uma rosa"

Símbolos: para cada rosa rosa ,␣ uma rosa é uma rosa
A vírgula seguida de espaço vira o separador ",␣". Os outros espaços somem.

5Árvore de codificação

Huffman monta uma árvore de baixo para cima:

  1. Começa com n folhas, uma para cada palavra do vocabulário, com sua frequência.
  2. A cada iteração, junta as duas árvores de menor frequência numa só. A raiz nova recebe a soma das frequências.
  3. Depois de n - 1 iterações, sobra uma árvore. O código de cada palavra é a sequência de bits (0 à esquerda, 1 à direita) da raiz até a folha dela.
Passo a passo: "para cada rosa rosa, uma rosa é uma rosa"

No fim, rosa (a mais frequente) recebe o código mais curto: 0.

6Árvore canônica

A árvore de Huffman minimiza o tamanho do arquivo comprimido. Mas não é única: trocar o filho da esquerda pelo da direita em qualquer nó gera outra árvore com a mesma razão de compressão.

A escolhida é a árvore canônica: aquela em que, em todo nó, a subárvore da direita nunca é mais baixa que a da esquerda. Na prática: os códigos curtos ficam à esquerda e a árvore "cresce para a direita", como na figura do passo anterior.

A árvore facilita visualizar e sugere métodos simples:

  • Codificar: percorre a árvore emitindo os bits das arestas.
  • Decodificar: os bits lidos escolhem as arestas até chegar numa folha.
Mas tem um problemaGuardar e percorrer a árvore é ineficiente em espaço e em tempo. É isso que motiva o próximo algoritmo: ele nem monta a árvore.

7Algoritmo de Moffat e Katajainen

Proposto em 1995, é baseado na codificação canônica e é linear em tempo e em espaço.

A grande sacadaEle calcula só os comprimentos dos códigos, não os códigos em si. A compressão é a mesma não importa quais códigos sejam usados, desde que os comprimentos sejam os de Huffman. Com os comprimentos em mãos, gerar os códigos é fácil (seção 8).

A entrada é um vetor A com as frequências em ordem decrescente. Para o exemplo: A = [4, 2, 1, 1, 1, 1] (rosa, uma, para, cada, ",␣", é). Tudo acontece dentro desse mesmo vetor: várias listas lógicas convivem nele, economizando memória.

O algoritmo tem três fases:

1. Combinação dos nós

Faz o trabalho do Huffman: junta os dois menores, repetidamente. No fim, A[2] tem o peso total da árvore e as outras posições guardam, para cada nó interno, o índice do seu pai.

2. Profundidade dos nós internos

Troca "índice do pai" por "profundidade": a raiz tem profundidade 0 e cada nó tem a do pai mais 1.

3. Profundidade das folhas

A partir de quantos nós internos há em cada nível, descobre em que nível fica cada folha. A profundidade da folha é o comprimento do código.

Fase 1: combinação dos nós

O vetor é percorrido da direita para a esquerda com três marcadores:

  • Folha: a próxima folha a ser usada (as menores frequências ficam no fim).
  • Raiz: o próximo nó interno a ser usado.
  • Prox: a próxima posição livre para guardar um nó interno novo.

A cada passo, escolhe o menor entre "próxima folha" e "próximo nó interno" (no empate, prefere o nó interno), duas vezes, e soma. Conforme as frequências são combinadas, viram pesos. Quando um nó interno é usado, a posição dele passa a guardar o índice do pai.

Traço do exemplo dos slides. Na linha k, A[2] = 10 é o peso da árvore inteira e A[3..6] = 2, 3, 4, 4 são os índices dos pais dos nós internos. A[1] não é usada: uma árvore com n folhas tem n - 1 nós internos.

Ver o pseudocódigo da fase 1 (só para apoio)
PrimeiraFase (A, n) { Raiz = n; Folha = n; for (Prox = n; Prox >= 2; Prox--) { /* Procura posição */ if ((não existe Folha) || ((Raiz > Prox) && (A[Raiz] <= A[Folha]))) { A[Prox] = A[Raiz]; A[Raiz] = Prox; Raiz = Raiz - 1; /* nó interno */ } else { A[Prox] = A[Folha]; Folha = Folha - 1; /* nó folha */ } /* Atualiza frequências */ if ((não existe Folha) || ((Raiz > Prox) && (A[Raiz] <= A[Folha]))) { A[Prox] = A[Prox] + A[Raiz]; A[Raiz] = Prox; Raiz = Raiz - 1; } else { A[Prox] = A[Prox] + A[Folha]; Folha = Folha - 1; } } }

O primeiro if pega o 1º nó da junção; o segundo pega o 2º e soma. A[Raiz] = Prox é o momento em que o nó usado passa a apontar para o pai.

Fase 2: profundidade dos nós internos

Agora o vetor é percorrido da esquerda para a direita. A raiz (A[2]) recebe 0. Para cada posição seguinte, a profundidade é a do pai mais 1: A[Prox] = A[A[Prox]] + 1. Funciona porque o pai sempre está à esquerda e já foi convertido.

Fim da fase 2 (profundidades)/01233

Leitura: a raiz está no nível 0; há um nó interno no nível 1, um no nível 2 e dois no nível 3.

Fase 3: profundidade das folhas

Ideia: num nível h, se há Disp nós disponíveis e u deles são internos, então os outros Disp - u são folhas com código de comprimento h. No nível seguinte, cada nó interno gera 2 filhos: Disp = 2 × u.

Nível hDisp (nós no nível)u (internos)Folhas nesse nível
0110
1211 folha com código de 1 bit (rosa)
2211 folha com código de 2 bits (uma)
3220
4404 folhas com código de 4 bits

Resultado: A = [1, 2, 4, 4, 4, 4], os comprimentos dos códigos na ordem do vocabulário.

Ver o pseudocódigo das fases 2 e 3 (só para apoio)
SegundaFase (A, n) { A[2] = 0; for (Prox = 3; Prox <= n; Prox++) A[Prox] = A[A[Prox]] + 1; } TerceiraFase (A, n) { Disp = 1; u = 0; h = 0; Raiz = 2; Prox = 1; while (Disp > 0) { while (Raiz <= n && A[Raiz] == h) { u = u + 1; Raiz = Raiz + 1; } while (Disp > u) { A[Prox] = h; Prox = Prox + 1; Disp = Disp - 1; } Disp = 2 * u; h = h + 1; u = 0; } } CalculaCompCodigo (A, n) { A = PrimeiraFase (A, n); A = SegundaFase (A, n); A = TerceiraFase (A, n); }

Na fase 3, o primeiro while conta os internos do nível h (u); o segundo grava h para cada folha do nível (Disp - u vezes).

8Códigos canônicos

Propriedades dos códigos canônicos:

  • os comprimentos seguem o algoritmo de Huffman;
  • códigos de mesmo comprimento são inteiros consecutivos.

Com os comprimentos de Moffat e Katajainen, a regra é simples:

  1. O primeiro código é só zeros.
  2. Cada próximo código é o anterior + 1; se o comprimento aumentar, desloca para a esquerda (acrescenta zeros no fim) até ter o tamanho certo.

Por que isso funcionaNenhum código é prefixo de outro (ex.: nenhum começa com 0 além de rosa). Assim, lendo os bits em sequência, sempre se sabe onde um código termina.

9Codificação e decodificação com Base e Offset

Como códigos de mesmo comprimento são consecutivos, não é preciso guardar a árvore nem a tabela de códigos. Bastam dois vetores pequenos, com MaxCompCod posições (o tamanho do maior código):

Base[c]

O valor inteiro do 1º código com comprimento c.

Base[1] = 0 Base[c] = 2 × (Base[c-1] + wc-1)

wc-1 = quantos códigos têm comprimento c - 1. Somar w pula esses códigos; multiplicar por 2 é acrescentar um bit.

Offset[c]

O índice no vocabulário da 1ª palavra com comprimento c.

cBase[c]Offset[c]Conta da Base
101regra inicial
2222 × (0 + 1) = 2 → 10
3622 × (2 + 1) = 6 → 110
41232 × (6 + 0) = 12 → 1100
Detalhe da tabela dos slidesNão existe código de comprimento 3, então Offset[3] não é usado para nenhuma palavra. O slide mostra Offset[3] = 2. Se você rodar o "Codifica" à mão para uma (i = 2) com esse valor, o laço avança até c = 3 e dá código errado. Com Offset[3] = 3 (o índice da próxima palavra), funciona. Vale confirmar com o professor qual convenção ele usa.

Codificar: índice → código

Descobre o comprimento c do código (o maior c cujo Offset ainda é ≤ i) e calcula:

Código = i - Offset[c] + Base[c]

Em palavras: "quantas palavras de comprimento c vêm antes dela" (i - Offset[c]) somado ao 1º código desse comprimento (Base[c]).

Exemplo: cada, i = 4. O comprimento é 4 e ela é a 2ª palavra de comprimento 4. Código = 4 - 3 + 12 = 13 = 1101.

Decodificar: bits → índice

Lê um bit por vez, montando o código. Enquanto o código, com mais um bit, for maior ou igual à Base do próximo comprimento, ainda não terminou: lê mais um bit. Quando para, usa a conta inversa:

i = Código - Base[c] + Offset[c]
cLeBitCódigoCódigo << 1Base[c+1]Continua?

Decodificando 1101: i = 13 - 12 + 3 = 4, ou seja, cada.

Ver os pseudocódigos Codifica e Decodifica (só para apoio)
Codifica (Base, Offset, i, MaxCompCod) { c = 1; while ((i >= Offset[c + 1]) && (c + 1 <= MaxCompCod)) c = c + 1; Codigo = i - Offset[c] + Base[c]; } Decodifica (Base, Offset, ArqComprimido, MaxCompCod) { c = 1; Codigo = LeBit (ArqComprimido); while (((Codigo << 1) >= Base[c + 1]) && (c + 1 <= MaxCompCod)) { Codigo = (Codigo << 1) | LeBit (ArqComprimido); c = c + 1; } i = Codigo - Base[c] + Offset[c]; }

10O processo completo

Compressão: 3 etapas

1ª etapa Vocabulário

Percorre o texto. Cada palavra é procurada no vocabulário: se existe, soma 1 na frequência; se não, é inserida. Usa uma tabela hash com tratamento de colisão, para inserir e pesquisar em O(1).

2ª etapa Códigos

Ordena o vocabulário por frequência, calcula os comprimentos (Moffat e Katajainen), constrói Base, Offset e Vocabulário e grava os três no início do arquivo comprimido. A hash é reconstruída lendo o vocabulário do disco.

3ª etapa Codificação

Percorre o texto de novo. Cada palavra é extraída, codificada (Codifica) e o código é gravado no arquivo comprimido.

Descompressão

É mais simples que a compressão:

  1. Lê Base, Offset e Vocabulário do início do arquivo comprimido.
  2. Lê os códigos, decodifica cada um (Decodifica) e grava a palavra correspondente no arquivo texto.
Ver os pseudocódigos (só para apoio)
Compressao (ArqTexto, ArqComprimido) { /* Primeira etapa */ while (!feof (ArqTexto)) { Palavra = ExtraiProximaPalavra (ArqTexto); Pos = Pesquisa (Palavra, Vocabulario); if Pos é uma posicao valida Vocabulario[Pos].Freq = Vocabulario[Pos].Freq + 1 else Insere (Palavra, Vocabulario); } /* Segunda etapa */ Vocabulario = OrdenaPorFrequencia (Vocabulario); Vocabulario = CalculaCompCodigo (Vocabulario, n); ConstroiVetores (Base, Offset, ArqComprimido); Grava (Vocabulario, ArqComprimido); LeVocabulario (Vocabulario, ArqComprimido); /* Terceira etapa */ PosicionaPrimeiraPosicao (ArqTexto); while (!feof (ArqTexto)) { Palavra = ExtraiProximaPalavra (ArqTexto); Pos = Pesquisa (Palavra, Vocabulario); Codigo = Codifica (Base, Offset, Vocabulario[Pos].Ordem, MaxCompCod); Escreve (ArqComprimido, Codigo); } } Descompressao (ArqTexto, ArqComprimido) { LerVetores (Base, Offset, ArqComprimido); LeVocabulario (Vocabulario, ArqComprimido); while (!feof (ArqComprimido)) { i = Decodifica (Base, Offset, ArqComprimido, MaxCompCod); Grava (Vocabulario[i], ArqTexto); } }

11Laboratório

Escreva qualquer frase e veja todo o processo acontecer: símbolos, frequências, comprimentos (calculados com o próprio algoritmo de Moffat e Katajainen), códigos canônicos, Base, Offset e o texto comprimido.

Uma árvore de Huffman para esse texto

A árvore mostra a junção dos menores. Os códigos da tabela são os canônicos, gerados só a partir dos comprimentos; com empates, uma árvore pode ter outro formato e mesmo assim gerar a mesma compressão.
